# 2026-07-24 설치 앱 localAppData 오류 수정
- 설치 후 실행 시 `Failed to get 'localAppData' path`가 메인 프로세스에서 발생했다. 앱 시작 직후 Electron `app.getPath("localAppData")`를 바로 호출하는 부분이 PC 환경에 따라 실패할 수 있다.
- 데이터 저장 위치는 `%LOCALAPPDATA%\BusinessTripProof`가 목적이므로, Electron 경로 조회가 실패하면 `process.env.LOCALAPPDATA`, 마지막으로 `homedir()\AppData\Local`을 fallback으로 사용한다.

# 2026-07-24 설치 앱 Not found 오류 수정
- 설치 후 앱 창에는 진입했지만 `Not found`만 표시됐다. 로컬 서버는 실행됐으나 정적 파일 기준 경로가 `process.cwd()`라 설치본 실행 위치가 앱 파일 위치와 다를 때 `travel-proof.html`을 찾지 못하는 구조였다.
- 서버의 기준 경로를 `TRAVEL_PROOF_APP_ROOT` 또는 `server.mjs` 위치로 잡아 개발 실행과 Electron 설치본 실행 모두 같은 앱 파일을 기준으로 정적 파일을 제공하도록 수정한다.

- 기존 입력 ID와 저장 버튼 ID는 유지해 저장 로직을 보존하고, 새로 추가한 역할 선택과 미리보기 요소만 JS로 연결한다.

# 2026-07-24 설정 화면 단순화
- 사용자는 설정 화면에서 복잡한 값 편집보다 `초기설정 다시 열기`와 `저장자료 확인`만 필요하다고 판단했다.
- 기존 기본 출발지, 도착지, 작성자, 조활비 인원 수, 저장 위치 값은 초기설정 팝업에서 다시 조정할 수 있으므로 설정 페이지 본문에서는 숨긴다.
- 저장자료 확인 카드는 사용자가 누르면 아래 저장자료 확인 영역을 펼치고 기존 미리보기 갱신 함수를 실행하는 진입점으로 사용한다.

# 2026-07-24 거리 캡처 항목 선택
- 일반 출장 수동입력은 `createManualProofGroup`에 현재 `startInput`과 `destinationInput` 값을 넘기고, 캡처 작업 생성 시 `group.start`와 `group.destination`을 그대로 사용한다. 따라서 수동입력 당시 입력칸을 다르게 작성하면 저장된 기본값이 아니라 화면 입력값 기준으로 캡처된다.
- 사용자는 통행료, 거리, 유가를 각각 선택해 캡처하고 싶어 한다. 거리와 유가 중 하나만 선택할 경우 증빙 이미지는 만들 수 있지만 유류대 금액 산출은 두 값이 모두 있어야 하므로, 금액 반영은 거리와 유가가 함께 선택된 경우로 제한하는 방향이 안전하다.
- 거리와 유가를 따로따로 캡처하는 사용 흐름을 고려해, 한쪽만 캡처되면 `pendingFuelCapture` 임시 행으로 거리값 또는 유가값과 저장 경로를 보관한다. 같은 그룹에서 반대쪽 값이 나중에 들어오면 기존 임시값과 합쳐 유류대·활동비 엑셀 행을 자동 생성하고 임시 행은 제거한다.
- 상단 2단계 안내 문구는 “거리·유가·통행료 중 필요한 항목을 선택한 뒤 캡처 시작”으로 바꾸고, 선택 UI는 세그먼트형 칩 카드로 정리했다.

# 2026-07-25 GitHub Releases 자동 업데이트
- 기존 앱에는 서명된 `release-manifest.json`과 설치파일을 공유 폴더에서 읽어 업데이트하는 자체 업데이트 구조가 이미 있다.
- 직원에게 매번 설치파일을 전달하지 않기 위해 기본 업데이트 채널을 GitHub Releases의 `latest/download/release-manifest.json`으로 바꾼다.
- 기존 공유 폴더 방식은 내부망이나 Drive 배포가 필요한 경우를 위해 `updateRoot`가 설정된 때만 fallback으로 유지한다.
- GitHub Release에는 설치파일과 같은 release에 `release-manifest.json`을 함께 올리면 앱이 manifest를 읽고 같은 release의 설치파일 URL을 계산해 다운로드한다.
